¿Qué es una página web multilingüe?

Es un sitio web que ofrece todo su contenido en varias lenguas, en todas sus partes: del menú al formulario de contacto. El visitante elige la suya y lee todo el sitio web en ella, sin depender del traductor del navegador.

No es lo mismo que un sitio web traducido a medias. En los sitios web multilingües bien hechos, cada traducción tiene su propia dirección, los motores de búsqueda saben qué traducción mostrar a cada persona y el cliente puede contactarte en su lengua. Para un autónomo, eso permite llegar a clientes extranjeros, a turistas o a quien prefiere leer en catalán, valenciano, gallego o euskera, con el mismo sitio web y el mismo precio.

Cómo se organiza un sitio web multilingüe para los motores de búsqueda

Search Central, la documentación oficial de Google para propietarios de sitios web, explica cómo gestionar un sitio web en varias lenguas. Estas son sus reglas básicas, útiles también si vas a montar tu web por tu cuenta.

Una URL distinta para cada traducción

Search Central recomienda usar una URL diferente para cada versión lingüística de una página, en lugar de cambiar el contenido con cookies o según la configuración del navegador. Describe tres opciones de estructura y desaconseja los parámetros en la dirección (del tipo ?loc=de):

  • Subdirectorios (por ejemplo, tunegocio.es/en/): costes de mantenimiento bajos; el servidor está en una única ubicación.
  • Subdominios (en.tunegocio.com): fáciles de configurar; la dirección puede no bastar para que los usuarios reconozcan la segmentación geográfica.
  • Dominio por país (tunegocio.fr): segmentación geográfica clara; cada sitio web se dirige a usuarios de un solo país.

Para un autónomo con una web .es o .com, los subdirectorios son una opción fácil de llevar: una sola web y una carpeta por lengua.

Las etiquetas hreflang

Su función es indicar al buscador, de forma clara, qué traducciones tiene cada página, para que muestre a cada usuario la que le corresponde; cada etiqueta apunta a una de ellas. Cada elemento link lleva tres atributos: el tipo de enlace (rel), la lengua y la dirección de esa traducción (atributo href). Se declaran de tres formas: con elementos link en la cabecera (el elemento head) del documento HTML, en el encabezado HTTP de la respuesta del servidor o en el sitemap XML; en ese archivo XML, cada entrada lista sus variantes con elementos xhtml:link. Los tres métodos son equivalentes.

Es importante respetar dos reglas. Cada traducción debe enumerarse a sí misma y a todas las demás, y todas deben apuntarse entre sí: si dos direcciones no se enlazan mutuamente, las etiquetas se ignoran. El valor x-default señala la página de reserva cuando la lengua del navegador no coincide con ninguna traducción disponible. Por ejemplo, para un sitio web en castellano y valenciano:

<link rel="alternate" hreflang="es" href="https://tunegocio.es/">
<link rel="alternate" hreflang="ca" href="https://tunegocio.es/va/">
<link rel="alternate" hreflang="x-default" href="https://tunegocio.es/">

El código ca sirve para el catalán y también para el valenciano: solo se admiten los códigos de idioma de dos letras de la norma ISO, que agrupa ambos bajo ca. Los códigos de región son opcionales y van detrás de un guion, por ejemplo es-ES para el español de España.

El atributo lang del elemento html

Su función es definir la lengua del contenido en el propio documento HTML. No hay que confundirlo con las etiquetas anteriores: aquellas relacionan las traducciones entre sí, y este atributo declara en qué lengua está escrito cada elemento. Es un atributo global: se puede poner en cualquier elemento del documento.

La recomendación del W3C, el organismo que publica la especificación HTML y otros estándares de la web, es clara: usa siempre este atributo en el elemento html para dejar definido el idioma predeterminado del documento, por ejemplo <html lang="ca"> en valenciano. Si un pasaje está en otra lengua, pon otro atributo en el elemento que lo rodea; si no hay ninguno adecuado, sirven los elementos span o div, por ejemplo <span lang="en">.

Los valores de estos atributos, llamados language tags, salen del registro de subetiquetas de idioma de la IANA, con las reglas de construcción que publica el IETF, y admiten variantes regionales y de escritura. Según el W3C, la especificación HTML ya no considera conforme la declaración con un elemento meta y http-equiv="Content-Language", así que no conviene utilizar ese método.

Ojo: el buscador no usa estas etiquetas ni ese atributo para identificar el idioma de una página: lo deduce del contenido visible. Una navegación traducida sobre párrafos en castellano sigue estando, para él, en castellano.

Codificación de caracteres: UTF-8

Para que la ñ, la ç o la l·l del valenciano se vean bien en pantalla, el W3C aconseja utilizar UTF-8 para todo el contenido: permite mostrar los caracteres de muchas lenguas, también mezcladas en un mismo documento HTML o formulario. Declarar la codificación no tiene efecto sobre el archivo: el texto tiene que estar guardado de verdad en ese formato, y una declaración en el encabezado HTTP prevalece sobre la del documento.

Una sola lengua por página y un selector visible

Search Central pide que el contenido y el menú de navegación de cada página estén en una sola lengua, y desaconseja poner dos lenguas en paralelo, en columnas. Recomienda también no redirigir automáticamente a los usuarios según la lengua que se les supone, y añadir enlaces a las otras versiones en todo el sitio web. En la práctica: un selector visible con cada lengua disponible, que lleve al mismo contenido y no a la portada. Es una cuestión de experiencia de usuario tanto como de SEO.

Traducción, localización e IA

La traducción pasa un texto de una lengua a otra. La localización va más allá: adapta el contenido al lector y a su mercado, con los formatos locales de fecha y moneda, las direcciones y números de teléfono, los ejemplos y la forma de nombrar tus productos y servicios. Un sitio multilingüe útil requiere las dos: una buena traducción y una localización cuidada, que también cuenta para el SEO.

Traducción automática e IA: un borrador, no una web

Los traductores automáticos y las herramientas de inteligencia artificial (IA) traducen en segundos, y varios programas de traducción para gestores de contenido las incorporan. Son un buen punto de partida para obtener un primer borrador, pero una traducción automática sin revisar puede equivocarse con los términos específicos de tu trabajo o sonar extraña justo donde el cliente decide si confía en ti. La IA ayuda a ganar tiempo; revisar cada traducción sigue siendo importante.

Google no prohíbe traducir un sitio web. Sus políticas contra el spam describen como abuso de contenido a gran escala generar muchas páginas con poco valor para los usuarios, incluso mediante transformaciones automáticas como las traducciones. Y su guía sobre versiones localizadas aclara que estas solo se consideran duplicadas si su contenido principal no está traducido: un menú traducido no basta.

SEO multilingüe: que te encuentren en cada lengua

El SEO multilingüe es la optimización de cada traducción de tu sitio web para las búsquedas que hace la gente en esa lengua. No basta con la traducción: hay que saber cómo busca cada audiencia y cuidar el posicionamiento de cada una.

Las búsquedas cambian de una lengua a otra

Traducir tus palabras clave no significa investigarlas. Lo que en castellano es «fontanero urgente Valencia», un residente británico lo buscará como «emergency plumber Valencia», a veces con «English speaking» delante. Escribe en el buscador tu servicio traducido y mira el autocompletado y las búsquedas relacionadas. Si ya tienes web, puedes obtener en el informe de rendimiento de Search Console las consultas reales con las que te encuentran, también las de quien te busca en otra lengua.

Títulos, descripciones y direcciones de cada traducción

Cada traducción lleva su propio título (el elemento title), su meta description y, si es posible, una dirección legible. El title y la descripción pueden ser lo primero que vea el usuario en la lista de resultados, antes de entrar en tu sitio web: son una parte importante de tu SEO que conviene optimizar.

Cómo elegir las lenguas de tu sitio web

Elige las lenguas que usan tus clientes y en las que puedes atenderlos. Un sitio web impecable en francés crea una expectativa que se rompe si nadie contesta en francés al teléfono o por WhatsApp.

  • Tu clientela actual: ¿en qué lengua te escriben, te llaman o te dejan reseñas?
  • Tu zona: en la costa y en las zonas turísticas, un sitio web multilingüe te acerca a residentes y visitantes extranjeros; en una comunidad con lengua cooficial, escribir también en ella te permite llegar a quien la usa a diario.
  • Los datos de tu web: Search Console y tu herramienta de analítica muestran desde qué países y con qué búsquedas llegan tus visitantes.
  • Tu capacidad de atender: ofrece solo las lenguas en las que puedes presupuestar y resolver una incidencia. El objetivo es que el cliente pueda contratar en su lengua de principio a fin.

Errores frecuentes en los sitios web multilingües

  • Traducir solo el menú. Los buscadores se fijan en el contenido visible, el visitante se encuentra con párrafos que no entiende y tu SEO no gana nada.
  • Mezclar dos lenguas en la misma página o duplicar cada párrafo en las dos.
  • Redirigir automáticamente según la ubicación o el navegador: el visitante ya no puede elegir.
  • Usar banderas en el selector. Una bandera representa un país, no una lengua: escribe el nombre de cada idioma en su propia lengua (Español, English, Français, Valencià).
  • Enlaces recíprocos ausentes: si una página enlaza a otra y esta no le devuelve el enlace, sus etiquetas se ignoran.
  • Olvidar otras partes del recorrido: el formulario, el mensaje de confirmación, el correo electrónico de respuesta, el mensaje predefinido de WhatsApp y la política de privacidad y de cookies.
  • Actualizar solo una versión: cuando cambias un precio o un horario, hay que cambiarlo en todas a la vez.
